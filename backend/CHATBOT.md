# NEXUS Conversational AI

The NEXUS Chatbot utilizes Google Gemini to generate responses adhering to the system prompt in `src/modules/chat/services/chatbot-system-prompt.ts` and the knowledge base in `src/modules/chat/services/chatbot-knowledge.ts`.

Configure the environment variables in your server runtime and restart the service:

```dotenv
CHATBOT_AI_ENABLED=true
GEMINI_API_KEY=<your_gemini_api_key>
CHATBOT_GEMINI_MODEL=<supported_gemini_model>
```

The model identifier must begin with `gemini-` and support structured output. When unconfigured, when Gemini produces an error or times out, or when invalid output is returned, the backend falls back to standard FAQ guidance (`engine: "FAQ"`). AI-generated answers return with `engine: "GEMINI"`.

## Conversational API Endpoints

The chatbot exclusively processes text; image uploads and file attachments are not supported. Request bodies with unexpected file attachments are rejected with an HTTP 400 Bad Request error. Image URLs within messages are treated purely as plain text strings; the backend does not fetch remote image contents to forward to Gemini.

- `POST /api/v1/chat/bot/messages`: Requires a Bearer JWT authentication token.
- `POST /api/v1/chat/bot/guest/messages`: Public endpoint for unauthenticated visitors, providing general guidance.
- Rate limiting: Restricted to a maximum of 20 requests per minute per IP or account, enforced via Redis.

```json
{
  "message": "The shop confirmed my order. What should I do next?",
  "history": [
    { "role": "user", "content": "I want to cancel my order" },
    { "role": "assistant", "content": "Has the shop confirmed your order yet?" }
  ]
}
```

The `history` property is optional, accepting up to 12 previous turns with a maximum of 2,000 characters per message. Only the `user` and `assistant` roles are permitted; client-supplied system prompts are strictly rejected. The backend is stateless and does not persist chat transcripts: callers supply message history when continuing an active discussion. Sensitive order data or credentials must not be passed in message history. Messages containing security keywords trigger static guidance; matching entries in message history are redacted before invoking Gemini.

Authenticated requests may include an `orderId` to query order statuses directly from the database, verifying buyer and seller access and returning with `engine: "ORDER"`. This branch bypasses AI generation; unauthenticated guests cannot supply an `orderId`. The AI assistant is not granted administrative or mutating tool privileges.

The response payload preserves a fixed schema containing `reply`, `engine`, `topic`, `sources`, and `actions`. Sources and suggested actions are selected from a predefined catalog rather than dynamic endpoints generated by the AI.

## Verification and Testing

Execute chatbot unit and API integration tests:

```bash
node --test backend/test/chatbot.test.mjs backend/test/chatbot-api.test.mjs
npm run build:backend
```

These automated tests mock Gemini API responses without incurring paid quota consumption. To verify live conversational quality, configure a valid API key and model identifier, then query the endpoints using multi-turn conversational histories.
